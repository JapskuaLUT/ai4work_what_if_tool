# Parity fixtures

Eighteen fixtures covering the validation cases the shared specification asks
for. Both systems — this What-If Tool and the main AI4Work education
application — should run these files and agree on **every component**, not just
on final stress, within `1e-6`.

## Layout

Each file is self-contained:

```jsonc
{
  "id": "05_exam_week",
  "description": "…which spec case this covers",
  "kind": "model" | "scenario",
  "input":  { … },
  "expected": { … }
}
```

`kind: "model"` fixtures feed a week series straight through the stress model
and compare `P_base`, `P_teach`, `P_home`, `P_assign`, `P_exam`, `P_over`,
`P_fatigue`, `R`, `S-hat`, `S` and the calibration bias, week by week.

`kind: "scenario"` fixtures feed a course plus an adjustment list through the
whole pipeline and compare the baseline and simulated trajectories, the
resulting weekly schedules, every adjustment outcome, the redistribution flows,
the extension records and the objective metrics.

## Coverage

| Fixture | Case |
|---|---|
| `01_light_week` | empty and light weeks, below every activation point |
| `02_ordinary_week` | ordinary lecture and laboratory week |
| `03_homework_heavy` | homework at and past the `P_home` saturation point |
| `04_assignment_heavy` | assignment hours at and past the `P_assign` saturation point |
| `05_exam_week` | exam weeks, including the 12-point floor at the smallest non-zero exam load |
| `06_combined_overload` | a combined week past the 32h overload threshold |
| `07_fatigue_carryover` | a high-stress week followed by normal weeks |
| `08_observed_blending` | same-week blending, plus the non-positive and out-of-range guards |
| `09_learned_bias` | bias learned from observed weeks, carried into unobserved ones |
| `10_assignment_moved` | assignment moved to another span |
| `11_assignment_hours_updated` | assignment hours changed |
| `12_assignment_extended` | deadline extended, with extension metadata |
| `13_exam_moved` | exam moved, including both neighbour effects |
| `14_exam_cancelled` | exam cancelled, all effects removed by the rebuild |
| `15_homework_moved` | homework moved and reduced, including an over-request |
| `16_teaching_redistribution` | lecture and lab cancellation with recorded flows |
| `17_invalid_inputs` | invalid dates, indices, negative hours, unknown references, duplicate ids |
| `18_soft_saturation` | raw stress far above range, verifying the soft cap and clipping |

## Running them

In this repository:

```sh
cd backend
bun test ./src/services/education/parity.test.ts
```

From the main application, the easiest route is
`POST /api/simulations/education/stress-model/evaluate`, which returns the same
component breakdown for a week series. Post each `kind: "model"` fixture's
`input.weeks` and diff against its `expected.weeks`.

## Where the expected values came from — read this

The **inputs** are handwritten. The **expected** blocks were generated by this
repository's implementation and frozen, by
[generate.ts](generate.ts).

That means these files currently prove that *this* implementation is
self-consistent and has not regressed. They do **not**, on their own, prove
that the two systems agree — for that, the main application has to run them and
report the diff.

**Status (2026-08-25):** the model owners have agreed to run these fixtures
against their implementation in their dev environment
([decisions.md §6](../decisions.md)), and confirmed the verification is
non-blocking. The complete set has been handed over. Until their run comes
back clean, "parity" here still means "implemented to the written
specification".

## A note on thresholds inside the fixtures

Scenario fixtures pin `stress_threshold_warning: 75` and
`stress_threshold_critical: 85` explicitly in their inputs. Those are the
specification's §8 values — deliberately, so the fixtures test the shared
specification and are unaffected by what any one tool displays. (This tool's
own display defaults are the course-model 45/55 per
[decisions.md §1](../decisions.md); a fixture must not depend on a default.)
With 75/85 pinned, every `warning_week_numbers` and `critical_week_numbers`
in the expected blocks is empty — that is correct, since those thresholds
belong to the total-stress scale and schedule-only output tops out at 60.45.

## Regenerating

```sh
bun run specifications/education_stress/parity/generate.ts
```

If a regenerated file differs from what is committed, the model changed. That
is a model-version bump and a conversation with the other system's owners — not
a fixture refresh. Bump `version` in
[constants.ts](../../../backend/src/services/stressModel/constants.ts) and say
what changed in [design.md](../design.md).
